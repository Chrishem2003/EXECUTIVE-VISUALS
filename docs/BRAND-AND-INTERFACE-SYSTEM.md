# CHRISHEM EXCLUSIVE VISUALS — Brand and Interface System

**Status:** active product identity  
**Applies to:** browser application, public landing pages, product metadata, exports, documentation and future companion clients.

## Brand promise

One connected creative production environment that takes a production from idea through creative direction, story development, generation, editing, enhancement, review and delivery.

The product name is **CHRISHEM EXCLUSIVE VISUALS**. It is the only product identity shown in the interface. External products are studied only as public capability references; their names, logos, proprietary assets, private APIs, prompts and source code are not copied into the product.

## Visual language

- Core canvas: near-black plum #090713.
- Primary panel: deep slate #121620.
- Secondary panel: dark violet slate #1B1730.
- Primary violet: #8B5CF6.
- Deep violet: #6D28D9.
- Soft violet: #A78BFA.
- Lavender highlight: #C4B5FD.
- Pale highlight: #DDD6FE.
- Text: cool white #F2F3F6; secondary text #A39BB8.
- Borders: muted violet slate #302A45.

Use violet for primary actions, active navigation, focus rings, progress and selected controls. Reserve pale lavender for high-contrast text and important highlights. Keep status colors semantically distinct: green for success, amber for caution, red for failure. Do not make every element glow.

## Experience principles

1. A single coherent workspace, not a directory of disconnected demos.
2. Professional information hierarchy: project context, active work, preview, controls and evidence.
3. Clear separation between planning, provider readiness, queued work, processing, review and completed deliverables.
4. Never present a placeholder or plan as generated media.
5. Show model/provider capability, availability, limits, estimated cost when verified, and unsupported inputs before execution.
6. Keep original assets, derivatives, versions and provenance connected.
7. Make advanced controls discoverable without overwhelming first-time users.
8. Responsive layouts must preserve timeline and review workflows on smaller screens.
9. Accessibility: keyboard navigation, visible focus, contrast, reduced motion and meaningful labels.
10. Use consistent spacing, typography, component states, empty states, error states and loading feedback across all workspaces.

## Brand acceptance checks

- Product name appears consistently in title, metadata, navigation, exports and documentation.
- No external product name, logo or copied visual asset appears in product-facing UI.
- Primary actions use the purple system and retain accessible contrast.
- All buttons perform real actions or are explicitly disabled with a reason.
- Readiness indicators reflect actual adapter and service health.
- Desktop, tablet and mobile layouts show no clipped navigation, forms or timeline controls.
